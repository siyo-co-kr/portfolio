## 배경

병원 안내·마케팅 문자를 보내려면 발송 대상 리스트를 먼저 만들어야 했습니다. 저를 포함한 **팀원 모두가 병원마다 같은 작업을 엑셀로 손수 반복**하고 있었습니다.

1. 전자차트에서 내려받은 **암호화된 엑셀**을 직접 열어 복호화
2. 병원마다 다른 컬럼명(`연락처` / `휴대폰번호` / `전화번호` …)을 매번 확인하며 정리
3. 하이픈·공백이 섞인 전화번호를 하나씩 다듬고 중복 제거
4. 내원일·생년월일 조건에 맞는 대상만 엑셀 함수로 골라내기
5. 정해진 양식에 옮겨 붙여 저장

## 문제

- **시간:** 리스트 하나를 만드는 데 **10~30분**이 걸렸고, 병원·리스트마다 이 작업이 반복돼 팀 전체의 업무 시간을 잡아먹었습니다.
- **휴먼 에러:** 수작업이다 보니 번호 누락, 중복 발송, 앞자리 0이 사라진 차트번호 같은 실수가 생길 수 있었습니다.
- **사람마다 다른 결과:** 같은 파일이라도 누가 작업하느냐에 따라 결과가 달라질 수 있었습니다.

> 개인의 불편이 아니라 **팀 공통의 반복 업무**라고 판단해, 저만 쓰는 스크립트가 아닌 **팀원 누구나 쓸 수 있는 프로그램**으로 만들기로 했습니다.

## 기획 · 설계

### ① 웹이 아닌 실행 파일(exe)로 — 민감 정보는 PC 밖으로 나가지 않게

다루는 데이터가 **병원의 환자 정보(이름, 연락처, 생년월일, 내원 기록)** 였기 때문에, 배포 방식을 정할 때 편의성보다 보안을 먼저 따졌습니다.

| 고려 사항 | 웹 서비스 | 실행 파일 (선택) |
|---|---|---|
| 데이터 이동 | 파일을 서버로 업로드해야 함 | **파일이 사용자 PC 밖으로 나가지 않음** |
| 외부 노출 | URL만 알면 누구나 접근 가능 | 프로그램이 설치된 PC에서만 실행 |
| 유출 지점 | 전송 구간, 서버 저장소, 로그 | 로컬 파일 시스템뿐 |
| 운영 부담 | 서버·인증·접근 권한 관리 필요 | 서버 없음 |

- 웹은 접근이 쉬운 만큼 환자 데이터가 **네트워크와 서버를 거치게** 됩니다. 업로드, 임시 저장, 로그 같은 유출 지점이 늘어납니다.
- 그래서 **PyInstaller로 빌드한 Windows 실행 파일(.exe)** 로 배포했습니다. 파일을 읽고, 복호화하고, 정제하고, 저장하는 전 과정이 **사용자 PC 안에서만** 이뤄집니다.
- 외부 서버로 보내는 통신이 없어 개인정보 유출 위험을 구조적으로 차단했습니다.

### ② 개발자가 아닌 팀원이 쓰는 도구로

- **3단계 사용 흐름:** 파일 선택 → 옵션 설정 → [필터링 및 저장]. 엑셀 함수나 코드를 몰라도 됩니다.
- **설치 없이 실행:** 폴더째 배포하고, 처음 실행하면 **바탕화면 바로가기를 자동으로 생성**합니다.
- **PC 환경 차이 대응:** OneDrive로 바탕화면 위치가 바뀐 PC, `PATH` 환경변수가 깨진 PC에서도 바로가기가 만들어지도록 외부 프로세스 대신 Windows COM(`IShellLink`)을 직접 호출했습니다.
- **결과를 믿고 쓸 수 있게:** 어느 단계에서 몇 건이 걸러졌는지, 어떤 컬럼을 사용했는지, 해석하지 못한 날짜가 몇 건인지를 완료 창에 보여줍니다. 결과를 다시 엑셀로 열어 검산하지 않아도 됩니다.
- **양식 그대로 출력:** 팀이 쓰던 결과 양식 엑셀 파일을 열어 값만 채워 저장하므로 서식이 100% 같습니다. 양식이 바뀌면 템플릿 파일만 교체하면 됩니다.

## 주요 기능

- 암호가 걸린 엑셀 파일을 프로그램 안에서 바로 복호화 (.xlsx / .xls)
- **컬럼명 유연 매칭:** 병원마다 다른 컬럼명을 표준 항목에 자동 매핑하고, 후보가 여러 개면 더 구체적인 이름을 우선 사용
- **시트·머리글 자동 탐색:** 머리글이 첫 행이 아니거나 데이터가 다른 시트에 있어도 필수 컬럼 위치를 찾아 읽음
- **원본 표기 보존:** 모든 값을 문자열로 다뤄 차트번호의 앞자리 0을 지키고, 0이 빠진 번호(`1012345678`)와 `+82` 표기는 자동 보정
- **날짜 자동 인식:** 날짜 셀, `2026-07-01`, `20260701`, 엑셀 일련번호를 모두 해석
- **필터:** 최근 N개월/년 내 내원, 오래 미내원한 대상, 생년월일 범위
- **전화번호 정제:** 특수문자 제거 → 형식 검증 → 중복 제거

## 기술적 고민

### UI와 처리 로직 분리

화면(`ui_components`)과 데이터 처리(`processors`)를 나눴습니다. 덕분에 GUI를 PySide6에서 tkinter로 바꿀 때 처리 로직은 손대지 않았고, 처리 로직은 GUI 없이 pytest로 테스트합니다.

### 실행 속도 — 3.05초 → 0.22초

팀원이 하루에도 여러 번 켜는 도구라서 켜지는 속도를 직접 측정했습니다.

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 빌드 방식 | 단일 exe (onefile) | 폴더 배포 (onedir) |
| 기동 시간 | 3.05초 (압축 해제만 2.17초, 71%) | **0.22초** |
| 데이터 처리 | pandas / numpy | 표준 라이브러리로 직접 구현 |
| 배포 용량 | 기준 | **절반 이하** |

- 수천 행을 한 번 훑는 작업이라 데이터프레임 라이브러리가 필요 없다고 판단해 pandas·numpy를 걷어냈습니다.
- 무거운 모듈은 시작 화면을 띄운 뒤에 불러오고(지연 임포트), 구형 `.xls` 전용 모듈은 `.xls`를 열 때만 불러옵니다.

### 조용히 사라지는 데이터 없애기

숫자로 읽으면 `00123`이 `123`이 되고, `.xls`의 전화번호는 `1012345678.0`이 됩니다. 그래서 셀을 전부 문자열로 읽고, 날짜는 허용할 형식을 명시한 전용 파서로 해석했습니다. 해석하지 못한 값은 버리지 않고 몇 건인지 완료 창에 알립니다.

## 결과

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 리스트 1건 작업 시간 | 10~30분 (수작업) | **약 10초** |
| 작업 단계 | 복호화 → 컬럼 정리 → 번호 정제 → 필터링 → 양식 작성 | 파일 선택 → 옵션 설정 → 저장 |
| 결과 일관성 | 작업자마다 다를 수 있음 | 누가 해도 같은 결과 |
| 데이터 이동 | — | 사용자 PC 안에서만 처리 |

- 리스트 1건당 **10~30분 걸리던 작업을 약 10초로 단축**
- 팀원 누구나 **파일 선택 → 옵션 설정 → 저장 3단계**로 리스트 정제를 끝낼 수 있게 됨
- 복호화, 컬럼 정리, 번호 정제, 필터링, 양식 작성까지 **수작업 5단계를 프로그램 하나로 대체**
- 같은 파일이면 누가 작업해도 **같은 결과**가 나오도록 처리 기준을 통일
- 환자 데이터가 **외부로 전송되지 않는 로컬 전용 구조**로 개인정보 유출 위험 차단
- 실행 시간 **3.05초 → 0.22초**, 배포 용량 **절반 이하**
- 약 3개월 동안 커밋 56개, v3.0.2까지 실사용 피드백을 반영하며 개선

## 개선 과정

실제로 쓰면서 나온 요구에 맞춰 계속 다듬었습니다.

1. PySide6 + pandas로 첫 버전 제작
2. 생년월일 필터, 장기 미내원 필터 추가
3. 결과 저장을 팀 양식(템플릿) 기반으로 변경, GUI를 tkinter로 전환
4. pandas 의존성 제거 및 엑셀 읽기 직접 구현
5. 기동 속도를 위해 onedir 빌드로 전환, 앱 아이콘 적용
6. 컬럼 매칭 로직을 별도 모듈로 분리하고 테스트 보강
